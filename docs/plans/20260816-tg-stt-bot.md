# tg_stt_bot — Telegram-бот расшифровки голосовых через parakeet STT

## Overview

Telegram-бот на Go, который расшифровывает голосовые сообщения и кружочки (video note) в текст и отвечает reply на исходное сообщение. Расшифровка — через собственный STT-сервис parakeet (OpenAI-совместимый API). Бот работает по long polling в ограниченном списке чатов (whitelist), в личке админа поддерживает сервисные команды, ошибки шлёт в отдельный сервисный канал.

- Скелет — по образцу `/Users/nikitakovalevskiy/dev/go_template`: слоистая чистая архитектура, поэтапный InitApp, graceful shutdown.
- Модуль `github.com/1kovalevskiy/tg_stt_bot`, go 1.26.5.
- Деплой — home_cluster (k8s), образ `ghcr.io/1kovalevskiy/tg_stt_bot` (манифесты вне скоупа этого плана).

## Solution Overview

Поток голосового: `bot.go` (вайринг) регистрирует тонкие хендлеры-диспетчеры через `RegisterHandlerMatchFunc` → диспетчер проверяет допуск чата (whitelist или личка админа — чистая функция в models), маппит update в чистую модель `models.IncomingAudio` и зовёт chat-контроллер → контроллер скачивает файл через telegram-провайдер → шлёт в STT-провайдер → разбивает текст по лимиту Telegram (чистая функция в models) → отвечает reply через telegram-провайдер. При ошибке — короткий ответ «не удалось расшифровать» в чат + `slog.Error`. Бот создаётся с `WithWorkers(4)`, чтобы долгая расшифровка не блокировала остальные апдейты (STT- и telegram-провайдеры должны быть безопасны для конкурентного использования).

Admin-контроллер — только команды в личке админа (`/status` — health parakeet, `/chats` — whitelist из конфига). Аудио из лички админа маршрутизируется диспетчером в тот же chat-контроллер (без дублирования логики).

Сервисный канал: fan-out slog-handler в `cmd/app/app/logs.go` — всё в stdout, записи уровня ERROR дополнительно асинхронно улетают в `service_chat_id` через telegram-провайдер. Контроллеры про канал не знают. Свои сбои отправки хендлер пишет только в stdout/stderr (не через slog — иначе рекурсия), при shutdown дренится через closer.

Чаты не из whitelist молча игнорируются.

## Technical Details

Структура:

```
cmd/app/

  app/
    app.go                    — App struct, InitApp: config → logs → providers → logSink → controllers → bot; RunApp, closers
    config.go, logs.go, providers.go, controllers.go, bot.go
internal/
  configs/                    — config.go, errors.go (+ config_test.go)
  models/                     — по файлу на структуру/функцию, errors.go (пустой — чистые модели ошибок не возвращают)
  providers/
    stt/                      — provider.go, transcribe.go, health.go, errors.go
    telegram/                 — provider.go, download_file.go, send_message.go, send_reply.go, errors.go
  controllers/
    chat-controller/          — controller.go, handle_voice.go, handle_video_note.go, transcribe_and_reply.go, errors.go
    admin-controller/         — controller.go, handle_command.go, errors.go
config.example.json           — в репо, плейсхолдеры
config.json                   — с секретами, в .gitignore
```

Конфиг (`config.example.json`):

```json
{
  "app": { "log_level": "INFO" },
  "telegram": {
    "token": "0000000000:PLACEHOLDER",
    "admin_id": 0,
    "service_chat_id": 0,
    "allowed_chats": []
  },
  "stt": { "base_url": "http://stt.stt.svc.cluster.local", "language": "", "timeout": "120s" }
}
```

- cleanenv: файл + env-переопределения (`TELEGRAM_TOKEN`, `TELEGRAM_ADMIN_ID`, `TELEGRAM_SERVICE_CHAT_ID`, `TELEGRAM_ALLOWED_CHATS`, `STT_BASE_URL`, `STT_LANGUAGE`, `STT_TIMEOUT`, `APP_LOG_LEVEL`), godotenv для локального `.env`.
- Валидация на старте: токен непуст, `admin_id` и `service_chat_id` != 0, `base_url` парсится, `timeout` — валидный duration, в `allowed_chats` нет нулевых элементов.
- `language` пустой → параметр не передаётся, parakeet сам определяет язык (голосовые на русском и английском).
- Ответ STT: JSON `{"text": "..."}`; ошибка — HTTP 400 + `{"error":{"message":...}}`, message включаем в обёрнутую ошибку.
- `stt.timeout` применяется в вайринге: `providers.go` создаёт `&http.Client{Timeout: cfg.GetSTTTimeout()}` и передаёт его STT-провайдеру как httpDoer.
- Скачивание файла Telegram: `GetFile(file_id)` → GET `https://api.telegram.org/file/bot<token>/<file_path>`. URL содержит токен → ошибки транспорта нельзя оборачивать как есть, токен редактируется.
- Лимит сообщения Telegram — 4096 **UTF-16 code units** (не рун); разбивка считает длину через `utf16.RuneLen`. Длинный текст → несколько сообщений: первое reply на исходное, остальные цепочкой.
- Bot API не отдаёт файлы > 20 MB (`getFile` откажет) — проверяем `FileSize` заранее и отвечаем «файл слишком большой».
- `models.Message.ID` в библиотеке — `int`, `Chat.ID` — `int64`: `IncomingAudio{ChatID int64, MessageID int, FileID string, FileSize int64}`.
- Импорт-коллизия `github.com/go-telegram/bot/models` vs `internal/models` — библиотечный алиасим как `tgmodels`.
