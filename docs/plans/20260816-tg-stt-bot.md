# tg_stt_bot — Telegram-бот расшифровки голосовых через parakeet STT

## Overview

Telegram-бот на Go, который расшифровывает голосовые сообщения и кружочки (video note) в текст и отвечает reply на исходное сообщение. Расшифровка — через собственный STT-сервис parakeet (OpenAI-совместимый API). Бот работает по long polling в ограниченном списке чатов (whitelist), в личке админа поддерживает сервисные команды, ошибки шлёт в отдельный сервисный канал.

- Скелет — по образцу `/Users/nikitakovalevskiy/dev/go_template`: слоистая чистая архитектура, поэтапный InitApp, graceful shutdown.
- Модуль `github.com/1kovalevskiy/tg_stt_bot`, go 1.26.5.
- Деплой — home_cluster (k8s), образ `ghcr.io/1kovalevskiy/tg_stt_bot` (манифесты вне скоупа этого плана).

## Solution Overview

Поток голосового: `bot.go` (вайринг) регистрирует тонкие хендлеры-диспетчеры через `RegisterHandlerMatchFunc` → диспетчер проверяет допуск чата (whitelist или личка админа — чистая функция в models), маппит update в чистую модель `models.IncomingAudio` и зовёт chat-контроллер → контроллер скачивает файл через telegram-провайдер → шлёт в STT-провайдер → разбивает текст по лимиту Telegram (чистая функция в models) → отвечает reply через telegram-провайдер. При ошибке — короткий ответ «не удалось расшифровать» в чат + `slog.Error`. Бот создаётся с `WithWorkers(4)` **и** `WithNotAsyncHandlers()`: по умолчанию библиотека запускает хендлер в отдельной горутине на каждый апдейт, воркеры только разгребают канал, и всплеск голосовых держал бы в памяти неограниченное число скачанных файлов. С `WithNotAsyncHandlers` число воркеров и есть предел одновременных расшифровок (STT- и telegram-провайдеры безопасны для конкурентного использования).

Admin-контроллер — только команды в личке админа (`/status` — health parakeet, `/chats` — whitelist из конфига). Аудио из лички админа маршрутизируется диспетчером в тот же chat-контроллер (без дублирования логики).

Сервисный канал: fan-out slog-handler в `cmd/app/app/logs.go` — всё в stdout, записи уровня ERROR дополнительно асинхронно улетают в `service_chat_id` через telegram-провайдер. Контроллеры про канал не знают. Свои сбои отправки хендлер пишет только в stdout/stderr (не через slog — иначе рекурсия), при shutdown дренится через closer.

Чаты не из whitelist молча игнорируются.

- cleanenv: файл + env-переопределения (`TELEGRAM_TOKEN`, `TELEGRAM_ADMIN_ID`, `TELEGRAM_SERVICE_CHAT_ID`, `TELEGRAM_ALLOWED_CHATS`, `TELEGRAM_API_TIMEOUT`, `TELEGRAM_DOWNLOAD_TIMEOUT`, `STT_BASE_URL`, `STT_LANGUAGE`, `STT_TIMEOUT`, `APP_LOG_LEVEL`), godotenv для локального `.env`. `cleanenv.ReadConfig` уже читает env поверх файла — второй `ReadEnv` не нужен.
- Валидация на старте: токен непуст, `admin_id` и `service_chat_id` != 0, `base_url` парсится, все три таймаута (`stt.timeout`, `telegram.api_timeout`, `telegram.download_timeout`) — валидные **положительные** duration (нулевой дедлайн срабатывает мгновенно), в `allowed_chats` нет нулевых элементов. Распарсенные значения кешируются в конфиге, геттеры не парсят строку на каждом вызове.
- `language` пустой → параметр не передаётся, parakeet сам определяет язык (голосовые на русском и английском).
- Ответ STT: JSON `{"text": "..."}`; ошибка — HTTP 400 + `{"error":{"message":...}}`, message включаем в обёрнутую ошибку.
- Таймауты — единственный источник дедлайна — контекст: `providers.go` создаёт `&http.Client{}` **без** своего `Timeout`, а каждый публичный метод провайдера строит дочерний `context.WithTimeout` со значением из конфига (исключение — `DownloadFile`, где `cancel` уезжает в возвращаемый ReadCloser, чтобы таймаут покрывал чтение тела).
- Скачивание файла Telegram: `GetFile(file_id)` → GET `https://api.telegram.org/file/bot<token>/<file_path>`. URL содержит токен → ошибки транспорта нельзя оборачивать как есть, токен редактируется.
- Лимит сообщения Telegram — 4096 **UTF-16 code units** (не рун); разбивка считает длину через `utf16.RuneLen`. Длинный текст → несколько сообщений, **каждое** reply на исходное: провайдер не возвращает ID отправленных сообщений, цепочку строить нечем. Сбой на середине списка чанков → пользователю уходит уведомление об ошибке, иначе обрезанная расшифровка выглядит как полная.
- Bot API не отдаёт файлы > 20 MB (`getFile` откажет) — проверяем `FileSize` заранее и отвечаем «файл слишком большой».
- `models.Message.ID` в библиотеке — `int`, `Chat.ID` — `int64`: `IncomingAudio{ChatID int64, MessageID int, FileID string, FileSize int64}`.
- Импорт-коллизия `github.com/go-telegram/bot/models` vs `internal/models` — библиотечный алиасим как `tgmodels`.
